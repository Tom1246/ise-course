# 数据来源与权威链

> **定位**：中文工作文档。回答"选课该以哪个源为准"。结论不是"选一个源"，而是**逐字段定权威**。

## 〇、本轮更正（重要）

前一轮我写过两句不准确的话，这里更正：

1. ~~"开课周/星期节次只有第三方源有"~~ → **错**。官方教务公开库
   `https://jwba.ucas.ac.cn/sc/public/coursePublic` 的**每门课的详情页**就带
   「上课时间（星期+节次）+ 上课地点 + 上课周次」。
2. ~~"官方工作簿没有校区字段、公开库没有容量"~~ → 前半句对（第三方源确实没有校区字段），
   但**官方公开库两者都有**：开课校区是它的一列，限选/已选也是。

## 一、五个来源，各自的位置

| 来源 | 形态 | 时态 | 玉泉路覆盖（2026 秋） | 权威字段 | 缺什么 |
| --- | --- | --- | --- | --- | --- |
| **❶ 官方教务公开库**<br>`jwba.ucas.ac.cn/sc/public/coursePublic` | 服务端渲染 HTML，无分页；POST `termId`+`campusCode` 过滤 | **当前态**（可随时重抓，带抓取时间戳） | **341 门**（campusCode=20） | 开课校区、课程属性、学分、课时、限选/已选、教师、**开课周+星期节次**（详情页） | 培养方案要求；"我实际选中的课" |
| **❷ 官方工作簿 xlsx**（开课计划表0828、核心课和专业课列表0828） | 教务发布的表格 | 计划态（发布后基本不变） | 732 条记录 / 414 门 | 开课学期（★ 只有它有） | 开课周、星期节次、容量 |

| **❹ 第三方工具内置课程库**（courseplanner 公开库） | 第三方整理 JSON | 快照态（**更新时间 2026-09-14 13:00**） | 347 门 | 教室、考试方式、授课方式（补充信息） | 无校区字段（只能靠编码第 18 位推）、无学期 |
| **❺ 你的手工周表** | 你排的 xlsx | 人工结果态 | 9 门课表 | 你已做出的取舍 | — |

**实测交叉验证**：❶ 与 ❹ 对同一门课的「星期 + 节次 + 周次」**完全一致**
（例：实用最优化算法 = 周三第 5–7 节，周 2–5、7–17）。两个独立管线得到同一结果 →
说明这两个字段在两边都可信，**但 ❶ 才是权威**（官方、可重抓、带校区与官方容量口径）。

## 二、逐字段定权威（这张表才是答案）

| 字段 | 权威源 | 理由 |
| --- | --- | --- |
| 开课校区 | **❶ 官方公开库** | 真字段；不必再用"课程编码第 18 位 = Y"去推 |
| 课程属性 / 学分 / 课时 | **❶ 官方公开库**（❷ 可互相印证） | 官方口径 |
| 开课周 / 星期节次 / 上课地点 | **❶ 官方公开库**（详情页） | 可重抓、带时间戳 |
| 限选 / 已选 / 剩余座位 | **❶ 官方公开库** | 官方口径；❹ 只是快照 |
| **开课学期** | **❷ 官方工作簿** | ❶ 不按课程给学期；❹ 完全没有 |
| 我实际选中的课 / 最终结果 | **❸ 选课系统** | 只有它有 |
| 是否培养方案要求 | **培养方案文件**（校发培养字〔2025〕92号） | 五个来源全无 |
| 教室 / 考试方式 / 授课方式（辅助） | ❹ 第三方 | ❶ 只给地点，不给考试与授课方式 |

**结论**：**以 ❶ 为主**，❷ 只用来补"开课学期"，❹ 降为交叉验证与辅助信息，❸ 只在需要"最终结果"时用。

## 三、爬取方案与合规边界

- **入口**：列表页 `POST /sc/public/coursePublic`（`termId` + `campusCode`），
  详情页 `GET /sc/course/coursetime/<id>`。**无需登录、无需验证码**——它就是给公众看的公开库。
- **实测规模**：2026 秋季全校 **2970 行**；玉泉路（campusCode=20）**341 行**。
- **脚本**：`scripts/fetch_official_db.py`（本仓库）
  - 带**本地 HTML 缓存**（`data/s2-public-listing/cache/`，已 gitignore）→ 可断点续爬、重跑不重下
  - 每轮记录**抓取时间戳**与**两份 sha256**（列表页、冻结输出）
  - 礼貌延时 `--sleep 0.25`，失败重试 3 次
- **合规**：只读公开页面、低频、不提交、不批量抢课。**不做自动选课。**
- **termId 备忘**：2026—2027 学年(秋)第一学期 = `89576`； (春)第二学期 = `89577`。
  校区 `campusCode`：玉泉路 `20`、中关村 `21`、雁栖湖 `22`。

## 四、官方数据的导入路径（第三方工具自己写的）

第三方站点在弹窗里明确提示：数据不新时，**去 SEP 系统的"学期课表"复制数据 → 粘贴到 Excel
（建议直接复制表格，不要点"导出"）→ 保存为 .xlsx → 在本页"课程目录"上传导入**。

也就是说，第三方工具的"官方工作簿"路径其实依赖人工从 SEP 复制粘贴 —— 这解释了两件事：
① 为什么导入结果可能有偏差（人工复制 + 导入器解析）；
② 为什么现在我们可以用 ❶ 直接把这一层**替换掉**。

## 五、还剩的两个缺口

1. **培养方案要求**：五个来源全无 → 必须人工输入（已在 `data/s5-programme/degree-requirements.json` 固化）。
2. **"我实际选中的课"**：只有 ❸ 选课系统有；封网后（9-18 之后）主要靠导出结果核对。

## 七、"考核方式"这类字段的出处（反查记录）

我实测反查了三个官方面（列表页 12 列、`coursetime` 时间地点、`courseplan` 课程大纲），**关键词命中全为 0**：

| 检索词 | jwba 列表页 | coursetime | courseplan | 官方工作簿 |
| --- | --- | --- | --- | --- |
| 考试方式 / 考核方式 | 0 | 0 | 0 | 无该字段 |
| 授课方式 | 0 | 0 | 0 | 无该字段 |
| 是否远程教学 / 助教 / 培养层次 | 0 | 0 | 0 | 无该字段 |

- `courseplan` 页是**课程大纲**（教学目的要求、预修课程、大纲内容章节表、教材信息、参考书、课程教师信息）——不含考核方式。
- 官方工作簿的字段只有 10 个：`序号/开课院系/课程编码/课程名称/开课校区/开课学期/课程属性/课程所属学科/学时/学分`。

**第三方的字段集**却是：`培养层次 / 所属学科专业 / 限选 / 已选 / 开课周 / 星期节次 / 教室 / 授课方式 / 考试方式 / 首席教授 / 主讲教师 / 助教 / 是否远程教学`。
它包含 **`限选`/`已选`**（只有**选课系统**才有）和 **`是否远程教学`/`助教`**（只有**登录后的教务/选课视图**才有）。
考核方式的取值也是一套下拉枚举：`闭卷笔试 / 课堂开卷 / 大开卷 / 读书报告 / 文献综述 / 其它（需说明）`。

**第三方站点自己声明了来源**：它的弹窗写着"如果发现本站数据库未及时更新，请前往 **SEP 系统的『学期课表』** 获取最新数据：
直接复制需要的课程数据，保留表头和完整的分段排课记录，粘贴到 Excel…在本页『课程目录』点击『上传课表』导入"，
并注明"内置课程库"由维护者定期更新（实测其更新时间为 2026-09-14 13:00）。

**结论**：
- **强证据**：jwba 三处 0 命中、工作簿无该字段、第三方字段集含只有选课系统才有的字段、第三方自述来源为 SEP。
- **属推断、未直接验证**：SEP「学期课表」页的具体列我没看到——**SEP 是登录门户**（`sep.ucas.ac.cn`，用户名/密码），
  没有登录态就进不去。所以这条是"第三方自述 + 字段特征"推出的，不是我看过原始页面。
- **彻底证实只需一步（你来，约 30 秒）**：登录 SEP 打开"学期课表"，看列里有没有
  「考试方式 / 授课方式 / 是否远程教学」。有 → 出处锁死。

**这件事的实际影响**（比"出处是谁"更重要）：

1. `考核方式` 是**人工从登录页复制粘贴**得来 → 存在复制误差（列错位、漏行）的可能，
   不能当作逐行可信的官方口径。
2. 它**不在任何公开接口里** → 我们不能自动刷新它，只能当**辅助字段**并在界面上标注来源（原型已标注"来源：第三方课程库"）。
3. 要拿到**官方口径**的考核方式，唯一路径是**登录 SEP 读取** → 想自动化只能设计成"半自动"：
   你登录（含验证码），我只做只读抓取。这与之前知网滑块时的分工一致。

### 决定性证据（2026-09-27 补）：原始快照的字段名就是 SEP 的表头

我们把先前抓取但**不入库**的原始下载（8,103,455 字节）重新校验了哈希：

```
sha256 = 7c6090e40801d1ba4ebf3665c54eafaf4ec6e5e3565d996df74e63fac53e8413   ← 与仓库记录一致 ✓
```

它每条记录里的 `fields` 字典，键恰好是 **19 个、且顺序与集合正是 SEP「学期课表」那一张表的表头**：

```
序号 / 开课单位 / 课程编码 / 课程名称 / 课程属性 / 培养层次 / 课时·学分 /
限选 / 已选 / 开课周 / 星期节次 / 教室 / 授课方式 / 考试方式 / 是否远程教学 /
所属学科/专业 / 主讲教师 / 首席教授 / 助教
```

其中 `限选`、`已选`、`是否远程教学`、`助教`、`培养层次` **只在登录后的 SEP 视图里存在**
（jwba 公开库与官方工作簿都没有）。第三方站点又恰好告诉用户"前往 SEP『学期课表』复制数据、
**保留表头**、粘贴到 Excel 导入"。→ **"第三方数据 = 人工从 SEP 学期课表复制粘贴" 得到实证。**

实测各字段有值条数（全库 2991 条）：除 `所属学科/专业` 2987、`主讲教师` 2558、`首席教授` 1528、
`助教` 232 外，其余字段 **2991 条全有值**。

**顺带得到两个可用的新字段**：

| 字段 | 取值分布 | 对本人的意义 |
| --- | --- | --- |
| `授课方式` | 课堂讲授为主 2560 / 课堂讨论为主 221 / 实验为主 70 / 其它（需说明）69 / 实践为主 31 | 判断"要不要到堂、是不是研讨型" |
| `是否远程教学` | **否 2991 / 2991** | 本学期无远程课，该字段对本学期无区分度 |

**固化方式（不破坏原有证据链）**：原冻结子集 `data/derived/course-library-snapshot.json` 的 schema 与
sha256 已被文档引用，**不能改**；因此新增一个独立哈希的冻结文件
`data/derived/sep-aux-fields.json`（+ `.sha256`），由 `scripts/freeze_aux_fields.py` 生成，
并在生成前**强制校验原始下载的 sha256 前缀**，不匹配就拒绝固化。

### 怎么彻底关掉这个议题（仍建议做，约 30 秒）

登录 SEP 打开「学期课表」，确认表头确实含 `考试方式 / 授课方式 / 是否远程教学`——
一旦确认，出处即闭环。若要自动化，则走**半自动**：你登录（含验证码），我只做只读抓取，
抓一份**带时间戳**的 SEP 快照，让"考核方式"从"人工复制的辅助字段"升级为可复现字段。
