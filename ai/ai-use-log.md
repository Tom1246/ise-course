## Domain input that came from the author, not from any tool

The priority model in `doc/priority-rules.md` rests on two criteria supplied by the author:

1. some courses must be taken *and* are offered only in this semester, so they cannot be postponed;
2. some courses matter but are grabbed quickly, so seats have to be taken early.

Neither criterion is derivable from the sources used here. The first becomes measurable once the semester
field is read (and becomes *unmeasurable* for the 6 codes absent from the official workbooks); the second is
measured as enrolled/capacity from the frozen public listing. The distinction between the two — and the fact
that they disagree, so the tool must emit a plan **and** a separate grab order — came from the author.

## Statements not verified, and therefore not relied on

- Whether *any* existing tool supports the week-range dimension. Only a few candidates were examined, so the
  brief says "none was found that joins these sources or carries the week range", not "no tool exists".
- How widespread the pain is: the only evidence of another person's experience is one classmate's account.
- Whether an empty capacity cell in the official workbooks means "no limit" or "not published". Treated as
  unknown throughout, never as unlimited.

## Numbers that must be measured, never estimated

- The baseline stopwatch measurement (the "baseline" figure in the brief): **about 30 minutes** for one full manual pass
  (edit one plan version, then re-check the whole plan). This is the author's own stopwatch measurement; no AI estimate is
  used and no value is invented.
